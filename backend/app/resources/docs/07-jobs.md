# 任务状态与排查

## 状态机

```
                    ┌────────── 管理员驳回 ──────────┐
                    │                               ▼
 提交 ──► 待审核 ──通过──► 排队中 ──派发──► 准备中 ──► 运行中
                    │           │                        │
        （关闭审核时直接排队）    └──── 用户/管理员终止 ──┐  │
                                                       ▼  ▼
                                        已终止 / 失败 / 已完成
```

| 状态 | 含义 |
|---|---|
| 待审核 | 等管理员通过，还没占用任何资源 |
| 排队中 | 已通过，等 GPU 或并发额度 |
| 准备中 | 已分配显卡，正在写配置、拉起进程 |
| 运行中 | 训练/评测进行中，日志实时推送 |
| 已完成 / 失败 / 已终止 | 结束态，可「重跑」按相同配置再提交一次 |

## 任务一直排队不动

| 原因 | 怎么确认 |
|---|---|
| 全局并发满了 | 平台管理 → 系统设置里的「全局并发任务数」 |
| 个人配额满了 | 平台管理 → 账号管理里的「并发任务上限」 |
| 空闲 GPU 不够 | 数据大屏上能看到哪几张卡被谁占用 |
| 申请卡数 > 本机总卡数 | 提交时就会被拦下，不会进队列 |

## 任务刚启动就失败

1. 打开任务详情 → **配置与命令**，把命令复制到终端跑一遍，错误信息会直观得多
2. 多数情况是对应框架的 python 环境缺依赖 —— 平台管理 → 工具链页会显示每个框架是否真的可用

## 常见失败原因

| 日志里的关键字 | 原因 | 处理 |
|---|---|---|
| `CUDA out of memory` | 显存不够 | 调小 batch / cutoff_len，或降低 rollout 显存占用比例 |
| `ModuleNotFoundError` | 框架环境缺依赖 | 检查 `PRT_*_PYTHON` 指向的环境 |
| `ValueError: template ...` | 对话模板不对 | 换模型时让平台自动带出 template |
| `进程已不存在` | 平台重启期间进程退出，或被 OOM killer 杀掉 | 看 `dmesg`；减小显存/内存占用 |
| `Verifier execution timed out` | 评测 verifier 超时 | 调大超时倍数 |

## 任务目录

每个任务独享两个目录，路径在详情页「概览」里：

| 目录 | 内容 |
|---|---|
| `data/jobs/<job_id>/` | `run.sh`（可复现的启动脚本，密钥已脱敏）、生成的配置文件、`stdout.log`、`metrics.json` |
| `data/outputs/<job_id>/` | checkpoint、Harbor 的 job 目录（含每个 trial 的轨迹） |

`run.sh` 可以直接在终端执行，用来在平台之外复现同一次训练。

## 终止与删除

- **终止**：向整个进程组发信号，torchrun worker、ray actor、docker 容器会一起回收
- **删除**：只删任务记录与工作目录，**产物默认保留**；确实要清理产物用
  `python scripts/manage.py gc --days 30`
