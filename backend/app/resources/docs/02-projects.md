# 项目

和 wandb / swanlab 里的 project 一样：**任务必须归属于某个项目**。进来先在顶栏选一个项目，
选完才能提交训练与评测。

## 为什么要有项目

一台机器上同时跑着好几条线的实验，光靠任务名区分很快就乱了。项目把「同一个目标下的一串实验」
收在一起，于是：

- 任务列表默认只看当前项目，不会被别人的实验刷屏
- 每个项目有负责人，谁在推进这件事一目了然
- 项目卡片直接给出任务总数、运行中、待审核和最近活动时间

## 可见性：列表共享，写操作收口

这是刻意的设计——团队里谁在跑什么应该透明：

| 操作 | 谁可以做 |
|---|---|
| 查看项目列表、搜索项目 | **所有登录用户** |
| 查看任务详情、日志、曲线 | **所有登录用户** |
| 在项目里提交任务 | 所有登录用户 |
| 改名 / 改描述 / 归档 / 删除项目 | 项目负责人、管理员 |
| 转交项目负责人 | 管理员 |
| 终止 / 删除某个任务 | 任务负责人、管理员 |

换句话说：**看是共享的，动是有主的**。看到别人的任务跑挂了可以直接点进去看日志，
但不能替对方终止。

## 常用操作

![项目选择界面](/api/handbook/assets/projects.png)

### 选项目 / 换项目

两个入口：

- **顶栏切换器**（logo 右侧）——快速切换，带项目名搜索
- **项目页 / 提交页的选择界面**——卡片式，带完整筛选，卡片上直接列出项目里的任务

选择会记在浏览器里，下次进来还是同一个项目。

### 联合筛选：找别人的任务

项目和任务在团队内共享，所以「找张三上周跑的那个评测」是常见需求。
选择界面上有三个条件，**同时生效（取交集）**：

| 条件 | 匹配什么 |
|---|---|
| 关键词 | 项目名 / 描述 / 标签，**以及项目里的任务名、备注、标签、任务 ID** |
| 负责人 | 该成员**参与**的项目（他在里面有任务，不必是项目负责人） |
| 训练 / 评测 | 含有该类型任务的项目（训练 = SFT + RL） |

关键**词也搜任务**这一点很重要：搜 `terminal` 会命中任务名里带 terminal 的项目，
即使项目名里没有这个词。命中的任务直接列在卡片上，一眼能确认是不是要找的那个，
点任务名就直接跳过去。

举例：关键词 `terminal` + 负责人 `张伟` + `评测`，结果就只剩张伟在 terminal
相关项目里跑的评测任务。

> 任务列表页也有同一组筛选（状态 / 类型 / 项目 / 负责人 + 关键词），
> 筛选条件会同步进 URL，可以直接把链接甩给同事。

### 新建项目

顶栏切换器里的「新建项目」，或者侧栏「项目」页右上角的按钮。

| 字段 | 说明 |
|---|---|
| 项目名称 | 团队内唯一，例如「Qwen3-4B 终端能力对齐」 |
| 描述 | 目标、约束、负责的模型——方便别人理解这个项目在做什么 |
| 标签 | 逗号或空格分隔，用于搜索 |

创建后会自动切换为当前项目。

### 归档还是删除

- **归档**：项目从列表里收起来（勾「含已归档」能看到），**不能再往里提交新任务**，
  历史任务全部保留。做完的实验线用这个。
- **删除**：只有**项目下没有任何任务**时才允许，否则接口会直接返回
  「项目下还有 N 个任务，无法删除；可以改为归档」。这是为了不让任务变成孤儿记录。

## 任务列表的筛选

| 条件 | 默认 | 说明 |
|---|---|---|
| 关键词 | 空 | 任务名 / 备注 / 标签 / 任务 ID |
| 状态 | 全部 | 待审核、运行中、已完成… |
| 类型 | 全部 | 监督训练 / 强化学习 / Agent 评测 |
| 项目 | **当前项目** | 切成「全部项目」可横向对比，此时表格多出一列「项目」 |
| 负责人 | **全部负责人** | 任务是团队共享的，所以默认看全员；下拉里第一项是「我」 |

筛选条件会写进 URL，链接可以直接分享。

## 常见问题

**提交时报「请先选择一个项目」**
顶栏没选项目。提交页会先拦一层，让你选或新建。

**提交时报「项目 X 已归档，无法提交新任务」**
换一个项目，或者把它恢复（负责人/管理员在项目页点「恢复」）。

**之前选的项目突然变成「未选择」**
它被删除或归档了。平台检测到失效会主动清掉本地记忆，重新选一个即可。
